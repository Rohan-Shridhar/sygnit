# Sygnit — Feature Priorities

## Priority Levels

| Priority | Meaning |
|---|---|
| P0 — Must Have | Essential features required for the initial release. |
| P1 — Should Have | Important improvements planned for upcoming releases. |
| P2 — Could Have | Optional enhancements for future consideration. |

## Feature Distribution

| Priority | Features | Target Release |
|---|---|---|
| P0 | Key generation, file hashing, file signing, repository manifest generation, signature verification, integrity checking, basic CLI. | v0.1.0 |
| P1 | Batch signing, JSON reports, configurable exclusions, improved CLI, Git integration, automation support. | v0.2.0 – v0.3.0 |
| P2 | Advanced key management, additional cryptographic algorithms, extended platform integrations, graphical interface. | Future |

## Prioritization Principles

1. Security and correctness come before convenience.
2. Core signing and verification must work before integrations.
3. Features should be prioritized according to user value and implementation effort.
4. New features must not compromise existing functionality.
